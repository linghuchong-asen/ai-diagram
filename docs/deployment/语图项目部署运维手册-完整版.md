## 1. 总览

### 1.1 项目简介

语图（ai-diagram）是一个"AI 对话生成流程图"的 Web 应用：

- **前端**：React 17 + Ant Design 4 + AntV X6 流程图编辑器，Vite 构建，BrowserRouter 路由。
- **后端**：NestJS 10 模块化单体，提供登录鉴权（JWT）、项目管理、文档保存、AI 对话（LangChain + DashScope qwen 系列模型，SSE 思考流）、AI 记忆与 Token 配额、执行轨迹观测等能力。
- **存储**：统一 PostgreSQL 单库（关系表 + JSONB 文档 + 记忆表 + 轨迹表），不依赖 MySQL/MongoDB/Elasticsearch；Redis 亦不需要部署（令牌态存 PG `auth_tokens` 表）。

**最小运行依赖只有 4 项**：PostgreSQL、后端容器、Nginx 容器、DashScope API Key（缺失时 AI 功能降级，其余功能正常）。

### 1.2 部署形态与拓扑

单机 Docker Compose 部署，三个容器：

```
                    ┌────────────────────────── 阿里云 ECS 8.140.203.51 ──────────────────────────┐
                    │                                                                             │
 用户浏览器 ──────► 80端口 │  ┌──────────────┐   /api/* 反代(去前缀)   ┌──────────────────┐        │
（公网 80/443）            │  │  yutu-nginx  │ ──────────────────────► │  yutu-backend    │        │
                          │  │  (Nginx前端) │ ◄──静态资源/SPA fallback │  (NestJS :3001)  │        │
                          │  └──────────────┘                          └────────┬─────────┘        │
                          │                                                     │ TypeORM        │
                          │                                            ┌────────▼─────────┐        │
                          │   /opt/yutu/uploads ◄───卷挂载─ /app/uploads │  yutu-postgres   │        │
                          │   /opt/yutu/logs    ◄───卷挂载─ /app/dist/logs  (PG 16 :5432)   │        │
                          │                                            └──────────────────┘        │
                          └─────────────────────────────────────────────────────────────────────────┘
                                        后端出网调用 DashScope：https://dashscope.aliyuncs.com/compatible-mode/v1
```

- Nginx 容器同时承担"前端静态资源服务"与"API 反向代理"两个角色。
- 后端容器 **不映射** 端口到宿主机公网，仅通过 Compose 内部网络被 Nginx 访问（运维可在宿主机 `127.0.0.1:3001` 本机调试，见 4.3）。
- PostgreSQL 容器 **不映射** 端口到宿主机，运维通过 `docker exec` 使用 psql/pg_dump。
- 前端请求统一走 `/api` 前缀，由 Nginx rewrite 去掉前缀转发后端（与开发环境 Vite proxy 行为完全一致）。
- AI 思考流（SSE，`/api/ai/think/:threadId`）要求 Nginx 关闭缓冲，已在本手册 nginx.conf 中配置。

**为什么不用 K8s**：单机单实例场景下 K8s 只增加复杂度而无收益；镜像 + Compose + tag 化发布已满足滚动更新与快速回滚需求。未来多实例时再演进。

## 2. 服务器环境准备

### 2.1 实例规格与前置检查

最低规格建议：2 核 4G（当前实例 3.5G 内存 + 4G swap 可正常运行）。执行前置检查：

```bash
# 确认系统与内核
cat /etc/os-release | head -2      # 预期：Ubuntu 22.04.x LTS
uname -m                            # 预期：x86_64

# 磁盘：/ 至少剩余 10G（Docker 镜像+数据约需 5G）
df -h / | tail -1

# 内存：确认 swap 存在（构建阶段 tsc 峰值内存较高）
free -h

# 端口占用检查（80/443/3001/5432 应无输出）
ss -tlnp | grep -E ':80 |:443 |:3001 |:5432 '

# 确认本机公网 EIP（阿里云元数据服务）
curl -s http://100.100.100.200/latest/meta-data/eipv4    # 预期：8.140.203.51
```

### 2.2 阿里云安全组配置

在阿里云控制台 → ECS 实例 → 安全组 → 配置规则，添加入方向规则：

| 协议 | 端口范围 | 授权对象 | 说明 |
|---|---|---|---|
| TCP | 22 | 运维人员出口 IP/32（如 `x.x.x.x/32`） | SSH，禁止 0.0.0.0/0 |
| TCP | 80 | 0.0.0.0/0 | HTTP 服务 |
| TCP | 443 | 0.0.0.0/0 | HTTPS（未启用 HTTPS 前可不加） |

出方向保持默认（允许全部）。**不要**为 3001/5432 添加入方向规则。

> 安全组在控制台配置，无法在 ECS 内部用命令核验。部署完成后按 5.7 节从外部验证连通性。

### 2.4 安装 Docker 与 Compose

通过阿里云镜像站安装 docker-ce 与官方 compose 插件：

```bash
# 1) 安装密钥与 apt 源
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

  > /etc/apt/sources.list.d/docker.list

# 2) 安装
apt-get update

# 3) 启动并自检
systemctl enable --now docker
```

### 2.5 配置镜像加速（国内拉取 Docker Hub 必需）

Docker Hub 在境内网络下不可直连，必须配置镜像加速器。**首选阿里云个人专属加速器**：

1. 登录阿里云控制台 → 容器镜像服务 ACR → 镜像加速器，获得专属地址，格式 `https://<你的ID>.mirror.aliyuncs.com`。
2. 写入配置：

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://<你的阿里云专属加速ID>.mirror.aliyuncs.com",
    "https://docker.1ms.run",
    "https://docker.m.daocloud.io"
  ]
}
EOF
systemctl restart docker
```

> 后两个为公共备用镜像，可用性随时间波动；专属加速器最稳定。若三个均不可用，参见 10.2 故障 8。

3. 验证拉取：

```bash
docker pull hello-world && docker run --rm hello-world   # 预期输出 Hello from Docker!
```

### 3.2 后端镜像 Dockerfile（deploy/Dockerfile.backend）

构建上下文为**仓库根目录**（`COPY serverend/...` 从根开始）。多阶段构建，构建阶段全量依赖编译，运行阶段仅生产依赖 + 编译产物：

```dockerfile
# syntax=docker/dockerfile:1
# ============ 构建阶段：全量依赖 + 编译 ============
FROM node:22-alpine AS builder
WORKDIR /build
# npm/pnpm 统一走华为云镜像（与 serverend/.npmrc 一致），pnpm 版本固定
ENV npm_config_registry=https://mirrors.huaweicloud.com/repository/npm/
RUN npm install -g pnpm@12.14.0

# 先复制依赖清单再 install，最大化利用 Docker 层缓存
COPY serverend/package.json serverend/pnpm-lock.yaml serverend/pnpm-workspace.yaml serverend/.npmrc ./
RUN pnpm install --frozen-lockfile

# 复制源码并构建：nest build → dist/src/main.js、dist/config/env.js
COPY serverend/ ./
RUN pnpm build

# ============ 运行阶段：仅生产依赖 + 产物 ============
FROM node:22-alpine
WORKDIR /app
ENV NODE_ENV=production TZ=Asia/Shanghai npm_config_registry=https://mirrors.huaweicloud.com/repository/npm/
RUN apk add --no-cache tzdata && npm install -g pnpm@12.14.0

# 按同一 lockfile 精确安装生产依赖
COPY serverend/package.json serverend/pnpm-lock.yaml serverend/pnpm-workspace.yaml serverend/.npmrc ./
RUN pnpm install --frozen-lockfile --prod

# 编译产物：dist/src/main.js（入口）、dist/config/env.js
COPY --from=builder /build/dist ./dist

# 关键目录：uploads 与应用日志的挂载点
# （代码以 __dirname 相对定位：容器内 /app/dist/src/* → /app/uploads、/app/dist/logs）
RUN mkdir -p /app/uploads /app/dist/logs

EXPOSE 3001
CMD ["node", "dist/src/main.js"]
```

**路径正确性说明**（依据代码事实，已核验）：
- `serverend/src/user/user.module.ts` 的 multer 存储目录为 `path.resolve(__dirname, '../../../uploads')`，编译后 `__dirname=/app/dist/src/user`，三级向上解析为 `/app/uploads`；
- `serverend/src/app.module.ts` 的静态资源根为 `path.resolve(__dirname, '../../', 'uploads')`，编译后 `__dirname=/app/dist/src`，解析同样为 `/app/uploads`；两者一致；
- `serverend/src/utils/log/logger.service.ts` 日志目录为 `__dirname/../../../logs` = `/app/dist/logs/<日期>/info.log|error.log`；
- `serverend/config/env.ts` 以 **CWD** 解析 `.env` / `.env.prod`，容器 `WORKDIR /app`，故 `.env.prod` 必须挂载到 `/app/.env.prod`。

### 3.4 Nginx 配置（deploy/nginx.conf）

三个关键行为：**① `/api` 前缀 rewrite（等价 Vite proxy 的 `rewrite: path.replace(/^\/api/, "")`）；② SSE 端点不缓冲；③ BrowserRouter 的 SPA fallback**。

```nginx
# 语图生产 Nginx 配置（构建进镜像 /etc/nginx/conf.d/default.conf）
server {
    listen 80;
    server_name _;

    # 头像等上传体积限制（后端 multer 同域上传）
    client_max_body_size 20m;

    # ---------- Gzip ----------
    gzip on;
    gzip_min_length 1k;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
    gzip_vary on;

    # ---------- 前端静态资源 ----------
    root /usr/share/nginx/html;
    index index.html;

    # 带 hash 的静态资源长缓存（js/css/svg/图片/字体）
    location ~* \.(js|css|svg|ico|png|jpg|jpeg|gif|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public";
        try_files $uri =404;
    }

    # ---------- API 反向代理 ----------
    # ^~ 优先于正则，保证 /api 下任何后缀（含 .js）都走代理
    location ^~ /api/ {
        # 尾斜杠：把 /api 前缀去掉再转发（与开发环境 Vite proxy 行为一致）
        proxy_pass http://backend:3001/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # SSE（/api/ai/think/:threadId）与长请求支持
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    # ---------- SPA fallback：其余路径统一回 index.html ----------
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

> `backend` 是 Compose 服务名，同网络内自动 DNS 解析，无需 IP。

### 3.5 构建命令与镜像 tag 规范

**tag 规范**：`yutu-backend:<YYYYMMDD>-<HHMM>`，同时打 `latest`。所有镜像仅存本机 Docker，不推远端仓库（如需推送，补充 `docker tag` + `docker push` 到 ACR 个人版即可）。

```bash
cd /root/workspace/ai-diagram

TAG=$(date +%Y%m%d-%H%M)

# 后端镜像（首次构建约 5-15 分钟，后续命中层缓存约 1 分钟）
docker build -f deploy/Dockerfile.backend -t yutu-backend:$TAG -t yutu-backend:latest .

# 前端镜像
docker build -f deploy/Dockerfile.frontend -t yutu-frontend:$TAG -t yutu-frontend:latest .

# 记录本次 tag（供 .env.prod 引用）
echo "本次构建 tag: $TAG"
```

## 4. 配置体系

### 4.1 `.env.prod` 完整模板（deploy/.env.prod.example）

> 以下模板在仓库中提交为 `deploy/.env.prod.example`；真实 `/opt/yutu/app/.env.prod` 由模板复制生成、填写后 `chmod 600`，**不入 git**。注意：`KEY=value` 等号两侧**不能有空格**（Docker Compose 解析要求；NestJS dotenv 亦兼容）。

```bash
# ================= 语图生产环境配置 =================
# 同时供两个消费方读取：
#   1) docker compose --env-file .env.prod 做变量替换（DB_USER/DB_PASSWD/DB_DATABASE、镜像 tag）
#   2) 挂载为容器内 /app/.env.prod，NestJS 启动时解析（生产优先于 .env）
# ====================================================

# ---- 镜像 tag（deploy.sh/rollback.sh 自动维护）----
YUTU_BACKEND_TAG=latest
YUTU_FRONTEND_TAG=latest

# ---- 运行标识 ----
NODE_ENV=production
PORT=3001

# ---- PostgreSQL（host 必须是 Compose 服务名 postgres）----
DB_HOST=postgres
DB_PORT=5432
DB_USER=yutu
DB_PASSWD=<openssl rand -base64 18 生成的数据库密码>
DB_DATABASE=flowchart_editor
# 首次建库专用：建表完成后【必须整行删除】并重启 backend（见 5.4 节）
DB_SYNCHRONIZE=true

# ---- 鉴权（安全）----
# 生成命令：openssl rand -hex 32
# 代码强制校验：缺失或等于 secret123456 时后端拒绝启动
```

### 4.3 docker-compose.yml（deploy/docker-compose.yml）

```yaml
# 语图生产编排。统一入口：
#   docker compose --project-directory /opt/yutu/app --env-file /opt/yutu/app/.env.prod <cmd>
name: yutu

x-logging: &default-logging
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"

services:
  postgres:
    image: postgres:16-alpine
    container_name: yutu-postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWD}
      POSTGRES_DB: ${DB_DATABASE}
      TZ: Asia/Shanghai
    volumes:
      - /opt/yutu/data/postgres:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 6
      start_period: 20s
    mem_limit: 768m
    logging: *default-logging

  backend:
    image: yutu-backend:${YUTU_BACKEND_TAG}
    container_name: yutu-backend
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      NODE_ENV: production
      PORT: 3001
    volumes:
      # NestJS 生产模式从 CWD 读取 .env.prod（config/env.ts 行为）
      - /opt/yutu/app/.env.prod:/app/.env.prod:ro
      # 用户上传目录（multer 与静态服务共用 /app/uploads）
      - /opt/yutu/uploads:/app/uploads
      # 应用日志（自定义 Logger 按日写 /app/dist/logs/<日期>/）
      - /opt/yutu/logs:/app/dist/logs
    healthcheck:
      # GET / 为公开端点，返回 {"code":0,"data":"Hello World!",...}
      test: ["CMD-SHELL", "wget -qO /dev/null http://127.0.0.1:3001/ || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 5
      start_period: 40s
    mem_limit: 1280m
    logging: *default-logging

  nginx:
    image: yutu-frontend:${YUTU_FRONTEND_TAG}
    container_name: yutu-nginx
    restart: unless-stopped
    depends_on:
      backend:
        condition: service_healthy
    ports:
      - "80:80"
    volumes:
      - /opt/yutu/logs/nginx:/var/log/nginx
    healthcheck:
      test: ["CMD-SHELL", "wget -qO /dev/null http://127.0.0.1/ || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 3
    mem_limit: 256m
    logging: *default-logging
```

**要点**：
- `healthcheck` 中 `$$` 双写：让 compose 忽略变量替换、由容器内 shell 展开；
- `mem_limit` 防止单容器吃满 3.5G 内存引发整机 OOM；
- 后端不做宿主机端口映射。临时调试命令（用后删除）：
  `sed -i 's/- "80:80"/- "80:80"\n      - "127.0.0.1:3001:3001"/' /opt/yutu/app/docker-compose.yml && docker compose ... up -d backend`

### 6.2 发版脚本（deploy/scripts/deploy.sh）

```bash
#!/usr/bin/env bash
# 语图发版：构建新镜像 → 更新运行目录 → 滚动更新 → 健康验证 → 失败自动回退
set -euo pipefail

REPO_DIR=/root/workspace/ai-diagram
APP_DIR=/opt/yutu/app
LOG=/opt/yutu/logs/deploy.log
NOTE=${1:-常规发版}

dc() { docker compose --project-directory "$APP_DIR" --env-file "$APP_DIR/.env.prod" "$@"; }
log(){ echo "[$(date '+%F %T')] $*" | tee -a "$LOG"; }

cd "$REPO_DIR"
TAG=$(date +%Y%m%d-%H%M)

log "== 发版开始 tag=$TAG 备注=$NOTE"

log "== 1/6 构建后端镜像"
docker build -f deploy/Dockerfile.backend -t "yutu-backend:$TAG" -t yutu-backend:latest .

log "== 2/6 构建前端镜像"
docker build -f deploy/Dockerfile.frontend -t "yutu-frontend:$TAG" -t yutu-frontend:latest .

log "== 3/6 同步工件"
rsync -a --delete --exclude='.env.prod' "$REPO_DIR/deploy/" "$APP_DIR/"
chmod +x "$APP_DIR"/scripts/*.sh

log "== 4/6 记录并切换镜像 tag"
PREV=$(grep -E '^YUTU_BACKEND_TAG=' "$APP_DIR/.env.prod" | cut -d= -f2)
sed -i "s|^YUTU_BACKEND_TAG=.*|YUTU_BACKEND_TAG=$TAG|"  "$APP_DIR/.env.prod"
sed -i "s|^YUTU_FRONTEND_TAG=.*|YUTU_FRONTEND_TAG=$TAG|" "$APP_DIR/.env.prod"
echo "$TAG $(date '+%F %T') $NOTE" >> "$APP_DIR/VERSIONS"

log "== 5/6 滚动更新容器"
dc up -d

log "== 6/6 健康验证（最长等待 150 秒）"
ok=0
for i in $(seq 1 15); do
  sleep 10
  b=$(docker inspect -f '{{.State.Health.Status}}' yutu-backend 2>/dev/null || echo starting)
  n=$(docker inspect -f '{{.State.Health.Status}}' yutu-nginx   2>/dev/null || echo starting)
  api=$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 http://127.0.0.1/api/ || echo 000)
  if [ "$b" = healthy ] && [ "$n" = healthy ] && [ "$api" = 200 ]; then ok=1; break; fi
  log "   第${i}次探测: backend=$b nginx=$n api=$api"
done

if [ "$ok" = 1 ]; then
  log "== 发版成功 tag=$TAG（上一版本 $PREV 已保留可回滚）"
else
  log "== 验证失败！自动回退到上一版本 $PREV"
  if [ -n "$PREV" ] && [ "$PREV" != "$TAG" ]; then
    sed -i "s|^YUTU_BACKEND_TAG=.*|YUTU_BACKEND_TAG=$PREV|"  "$APP_DIR/.env.prod"
    sed -i "s|^YUTU_FRONTEND_TAG=.*|YUTU_FRONTEND_TAG=$PREV|" "$APP_DIR/.env.prod"
    dc up -d
    log "== 已回退到 $PREV，请查 docker logs yutu-backend 定位失败原因"
  else
    log "== 无上一版本可回退，保持现状，请人工介入"
  fi
  exit 1
fi
```

### 6.3 回滚脚本（deploy/scripts/rollback.sh）

```bash
#!/usr/bin/env bash
# 语图回滚：回退到指定历史 tag（默认上一个版本）
set -euo pipefail
APP_DIR=/opt/yutu/app
LOG=/opt/yutu/logs/deploy.log
dc() { docker compose --project-directory "$APP_DIR" --env-file "$APP_DIR/.env.prod" "$@"; }
log(){ echo "[$(date '+%F %T')] $*" | tee -a "$LOG"; }

TARGET=${1:-}
cd "$APP_DIR"
if [ -z "$TARGET" ]; then
  # 取当前 tag 在 VERSIONS 中的上一条
  CUR=$(grep -E '^YUTU_BACKEND_TAG=' .env.prod | cut -d= -f2)
  TARGET=$(grep -E '^[0-9]{8}-[0-9]{4} ' VERSIONS | awk '{print $1}' | grep -vx "$CUR" | tail -1)
fi
[ -n "$TARGET" ] || { log "无可回滚版本"; exit 1; }
docker image inspect "yutu-backend:$TARGET"  >/dev/null 2>&1 || { log "镜像 yutu-backend:$TARGET 不存在"; exit 1; }
docker image inspect "yutu-frontend:$TARGET" >/dev/null 2>&1 || { log "镜像 yutu-frontend:$TARGET 不存在"; exit 1; }

log "== 回滚开始 $CUR -> $TARGET"
sed -i "s|^YUTU_BACKEND_TAG=.*|YUTU_BACKEND_TAG=$TARGET|"  .env.prod
sed -i "s|^YUTU_FRONTEND_TAG=.*|YUTU_FRONTEND_TAG=$TARGET|" .env.prod
dc up -d

ok=0
for i in $(seq 1 15); do
  sleep 10
  api=$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 http://127.0.0.1/api/ || echo 000)
  b=$(docker inspect -f '{{.State.Health.Status}}' yutu-backend 2>/dev/null || echo starting)
  [ "$api" = 200 ] && [ "$b" = healthy ] && { ok=1; break; }
done
[ "$ok" = 1 ] && log "== 回滚成功: $TARGET" || { log "== 回滚后验证未通过，人工检查"; exit 1; }
```

回滚执行：

```bash
bash /opt/yutu/app/scripts/rollback.sh          # 回到上一版
bash /opt/yutu/app/scripts/rollback.sh 20261017-2230   # 回到指定版本
```

### 6.4 回滚分级策略

| 层级 | 场景 | 操作 |
|---|---|---|
| 代码回滚 | 新版本功能异常 | `rollback.sh`（镜像 tag 切换，秒级完成，不动数据） |
| 配置回滚 | 改 `.env.prod`/nginx 后异常 | `git diff` 对照模板改回 → `dc up -d`（配置文件在宿主机，立即生效） |
| 数据回滚 | 数据损坏/误删 | 停止写入 → 按 8.4 恢复流程回灌昨日备份 |
| AI 行为回滚 | Prompt/模型变更导致效果劣化 | `.env.prod` 改回原 `LLM_MODEL_*` → `dc restart backend`（模型经环境变量配置，无需重建镜像） |

### 7.2 巡检脚本（deploy/scripts/inspect.sh）

```bash
#!/usr/bin/env bash
# 语图每日巡检：全部通过输出 [ OK ]，异常输出 [FAIL]（grep FAIL 快速定界）
set -uo pipefail
say(){ echo "$1 $2"; }
ok(){ say "[ OK ]" "$*"; }
fail(){ say "[FAIL]" "$*"; }

echo "==== 语图巡检 $(date '+%F %T') ===="

# 1) 容器状态与健康
for c in yutu-postgres yutu-backend yutu-nginx; do
  st=$(docker inspect -f '{{.State.Status}}' $c 2>/dev/null || echo missing)
  h=$(docker inspect -f '{{if .State.Health}}{{.State.Health.Status}}{{else}}n/a{{end}}' $c 2>/dev/null)
  [ "$st" = running ] && [ "$h" != unhealthy ] && ok "$c 运行中 (health=$h)" || fail "$c 状态异常: $st/$h"
done

# 2) 磁盘
usage=$(df / | awk 'NR==2{gsub("%","");print $5}')
[ "$usage" -lt 85 ] && ok "磁盘使用 ${usage}%" || fail "磁盘使用 ${usage}% ≥85%，需清理"

# 3) 内存
free -m | awk 'NR==2{printf "%s 内存: %sMB/%sMB\n",($2-$7>3000?"[FAIL]":"[ OK ]"),$3,$2}'

# 4) PostgreSQL 连通 + 核心表存在
if tables=$(docker exec yutu-postgres psql -U yutu -d flowchart_editor -tAc \
  "SELECT count(*) FROM information_schema.tables WHERE table_schema='public'" 2>/dev/null) && [ "${tables:-0}" -ge 10 ]; then
  ok "PG 连通，public 表数量: $tables"
else
  fail "PG 连接失败或表数量异常: ${tables:-无}"
fi

# 5) 后端 API
code=$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 http://127.0.0.1/api/ || echo 000)
[ "$code" = 200 ] && ok "后端 API HTTP 200" || fail "后端 API HTTP $code"

# 6) 前端
code=$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 http://127.0.0.1/ || echo 000)
[ "$code" = 200 ] && ok "前端首页 HTTP 200" || fail "前端首页 HTTP $code"

# 7) 近 24h 应用错误量
today=/opt/yutu/logs/$(date +%F)
errs=$(grep -c ERROR "$today/error.log" 2>/dev/null || echo 0)
[ "$errs" -lt 50 ] && ok "当日应用 ERROR $errs 条" || fail "当日应用 ERROR $errs 条，需人工检查 $today/error.log"

# 8) 备份新鲜度
latest=$(find /opt/yutu/backup -name 'yutu-db-*.dump' -printf '%T@ %p\n' 2>/dev/null | sort -rn | head -1 | cut -d' ' -f2-)
if [ -n "$latest" ]; then
  age=$(( ($(date +%s) - $(stat -c %Y "$latest")) / 86400 ))
  [ "$age" -le 1 ] && ok "最近备份 ${age} 天前: $latest" || fail "最近备份已 ${age} 天未更新"
else
  fail "未发现数据库备份"
fi

# 9) 容器异常重启检测
for c in yutu-postgres yutu-backend yutu-nginx; do
  n=$(docker inspect -f '{{.RestartCount}}' $c 2>/dev/null || echo 0)
  [ "$n" -lt 3 ] || fail "$c 已自动重启 ${n} 次（疑似崩溃循环）"
done

echo "==== 巡检结束 ===="
```

### 8.1 备份策略

| 对象 | 方式 | 频率 | 保留 | 位置 |
|---|---|---|---|---|
| PG 全库 | `pg_dump` 自定义格式（-Fc，支持并行恢复/选择性恢复） | 每日 02:30 | 14 天 | `/opt/yutu/backup/yutu-db-*.dump` |

### 8.2 备份脚本（deploy/scripts/backup.sh）

```bash
#!/usr/bin/env bash
# 语图每日备份：PG 全库 + uploads，保留 14 天
set -euo pipefail
BACKUP_DIR=/opt/yutu/backup
TS=$(date +%Y%m%d-%H%M%S)
KEEP_DAYS=14
mkdir -p "$BACKUP_DIR"

# 1) 数据库（pg_dump 自定义格式）
docker exec yutu-postgres pg_dump -U yutu -d flowchart_editor -Fc -f "/tmp/yutu-db-$TS.dump"
docker cp "yutu-postgres:/tmp/yutu-db-$TS.dump" "$BACKUP_DIR/yutu-db-$TS.dump"
docker exec yutu-postgres rm "/tmp/yutu-db-$TS.dump"

# 2) uploads
tar -czf "$BACKUP_DIR/yutu-uploads-$TS.tar.gz" -C /opt/yutu uploads

# 3) 轮转
find "$BACKUP_DIR" -name 'yutu-db-*.dump'      -mtime +"$KEEP_DAYS" -delete
find "$BACKUP_DIR" -name 'yutu-uploads-*.tar.gz' -mtime +"$KEEP_DAYS" -delete

echo "[$(date '+%F %T')] 备份完成: yutu-db-$TS.dump ($(du -h "$BACKUP_DIR/yutu-db-$TS.dump" | cut -f1)), yutu-uploads-$TS.tar.gz ($(du -h "$BACKUP_DIR/yutu-uploads-$TS.tar.gz" | cut -f1))"
```

### 8.4 恢复手册（Runbook）

> 前提：已知目标备份文件名，如 `yutu-db-20261017-023000.dump`。

```bash

dc() { docker compose --project-directory /opt/yutu/app --env-file /opt/yutu/app/.env.prod "$@"; }
DUMP=/opt/yutu/backup/yutu-db-20261017-023000.dump
UP=/opt/yutu/backup/yutu-uploads-20261017-023000.tar.gz

# 1) 停止写入方（后端；nginx 保持可给用户报维护页也可一并停）

# 2) 清库重灌（dropdb 后 createdb，再 pg_restore）
docker cp "$DUMP" yutu-postgres:/tmp/restore.dump
docker exec yutu-postgres dropdb   -U yutu --if-exists flowchart_editor
docker exec yutu-postgres createdb -U yutu flowchart_editor
docker exec yutu-postgres pg_restore -U yutu -d flowchart_editor --no-owner /tmp/restore.dump
docker exec yutu-postgres rm /tmp/restore.dump

# 3) 恢复 uploads（tar 打包时根目录为 uploads/，解压到 /opt）
tar -xzf "$UP" -C /opt

# 4) 起服务并验证
dc up -d backend
docker logs --since 2m yutu-backend | grep '服务启动成功'
curl -s http://127.0.0.1/api/        # 预期 {"code":0,...}
docker exec yutu-postgres psql -U yutu -d flowchart_editor -tAc \
  "SELECT count(*) FROM information_schema.tables WHERE table_schema='public'"
# 预期：与备份时一致（≥ 11）

# 5) 业务验证：浏览器登录一个历史账号，打开历史项目确认文档数据完整
```

**部分恢复（误删单表/单项目）**：pg_dump 自定义格式支持选择性恢复，例：`pg_restore -U yutu -d flowchart_editor --no-owner --table=project /tmp/restore.dump`。

### 9.1 密钥管理规范

| 项 | 规范 |
|---|---|
| 存储 | 仅 `/opt/yutu/app/.env.prod`（600 权限）+ 密码管理器；仓库只有 `.env.prod.example` 模板 |

```bash
# ② JWT 密钥轮换（全体用户登出，前端需重新登录；auth_tokens 旧令牌自然失效）
NEW=$(openssl rand -hex 32)
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$NEW|" /opt/yutu/app/.env.prod
dc up -d backend
```

### 10.3 FAQ

**Q1：为什么 Redis/Elasticsearch 没有部署环节？**
代码事实：令牌态存 PG `auth_tokens`（`TOKEN_STORE=pg`）；执行轨迹/日配额落 PG；全文检索用 PG tsvector + GIN（`projectSearch` 模块）。运行时无任何 Redis/ES 连接，部署它们只会增加故障面。

**Q2：头像功能为什么在验证清单里？**
没有。前端当前版本不消费头像字段，且 `user/update` 的 multer 拦截器处于注释状态，属历史遗留接口——部署验证不含此项；`/opt/yutu/uploads` 挂载是为后续功能启用预留。

**Q3：改了 `.env.prod` 如何生效？**
`dc up -d backend`（重建容器读取新环境）。仅 nginx.conf 变化才需要重建前端镜像（配置打进了镜像）。

**Q4：想直连数据库看数据？**
```bash
docker exec -it yutu-postgres psql -U yutu -d flowchart_editor
```

**Q5：如何确认当前运行的是哪个版本？**
```bash
grep -E '^YUTU_(BACKEND|FRONTEND)_TAG=' /opt/yutu/app/.env.prod
tail -5 /opt/yutu/app/VERSIONS
```

**Q6：AI 降级模式（未配 DashScope Key）影响面？**
流程图编辑、项目管理、文档保存、登录全部正常；AI 对话生成走规则/模板降级路径，效果有限。配置 Key 后 `dc up -d backend` 即恢复完整 AI 能力，无需改代码。
