## 七、关键设计决策（防止接手人重新纠结）

1. **复杂度判断绝不单独调模型**：复用意图分类那次 medium 调用顺带输出 complexity——省下的钱不能被分类调用吃掉。
2. **拿不准默认旗舰**（质量优先）：误判到轻量的代价是「用户觉得产品变笨」，比多花钱更伤。
3. **误判兜底靠事后升级而非前置精判**：轻量档生成反思连续失败且下一次即末次重试 → 升级旗舰再试一次，旗舰也失败才转人在回路（既有行为不变）。
4. **试用强制 flash**（source=trial-force），忽略一切偏好；但末次重试升级链对试用同样生效——一次失败的试用（名额浪费+转化流失）比多花一次旗舰调用更贵。
5. **手选旗舰=会员权益**：后端 `quota.isVipNow()` 闸门（非会员平滑回落 Auto，不报错）+ 前端置灰「· 会员」双保险；**Auto 路由不受会员限制**（复杂请求质量优先）。
6. **isVip 按需查询**：仅当用户手选 flagship 时 createThread 才查一次用户表，Auto 请求零额外开销。
7. **`--yt-gradient` 令牌重定义为实色而非删除**：历史引用（AI 悬浮球等）自动降级，零破坏。
8. **节点功能色不动**：node-type-config 的语义色板是内容级辨识色，不是 UI chrome。
9. 工程细节：antd4 Select 下拉用 `dropdownClassName`；前端 check 断言用 `assertTrue` 系列、`finish('label')` 带标签；后端 zod 是 4.0.17（`z.record` 两参数）。

## 八、风险与注意事项

- **graph.ts 的 5 处 escalate 接入点**是用 replace_all 打在 `loop.consume(); state.rewriteCount = loop.retryCount;` 模式之后的，若日后重试语义改动需同步检查。
- **INTENT_SYSTEM_PROMPT 改 JSON 输出**：线上模型若不配合仍走「单词/松散包含」回退解析（兼容保留），但复杂度字段会缺省 → 路由退回规则/默认旗舰，行为安全。
- **试用强制 flash 后的转化观察**：qwen-turbo 生成质量是否影响试用转化率需数据验证；换更强轻量模型只需改 env `LLM_MODEL_FLASH`，无需发版。
- **配额口径变化**：模板命中轮不再扣生成次数（修复），统计上「真实 LLM 生成次数」会略降、模板使用占比上升——增长看板解读数据时注意。
- 两个 graph spec 里已打的两轮 flash 桩补丁与最终 `getModelForTier` 修复并存无害，但可在提交前顺手把桩整理成一个共享 fake 对象。
