# 后端简历技术描述生成计划

## Summary
为 AI 流程图编辑器后端项目生成简洁的简历用技术描述文档，采用 Markdown 格式，内容精炼，突出架构思维、技术亮点和**生产环境落地实践经验**（解决上线产品实际遇到的问题），适合直接写入简历。

## Current State Analysis
- 项目后端基于 NestJS + TypeScript 构建，是一个可上线的完整产品
- 已实现 MySQL + MongoDB 双数据源存储
- 已集成 LangChain + 通义千问的 AI 能力，含 SSE 流式响应
- 已实现 JWT 认证、全局异常处理、统一响应、事务管理等工程化能力
- 已实现 QueryRunner 事务处理，解决项目删除时的级联数据一致性问题
- 已实现文件上传导出功能
- Redis 模块依赖已引入
- 用户反馈需要突出落地经验和解决线上实际问题的能力

## Proposed Changes

### 1. 更新简历技术描述 Markdown 文件
- **文件**：`d:\userProjects\流程图编辑器项目\ai-diagram\后端简历技术描述.md`
- **内容结构**：
  - 项目名称 + 技术栈一行展示
  - 项目描述（1-2句话概括项目定位）
  - 技术亮点（6条，每条突出"**遇到什么生产问题 → 采用什么技术方案 → 达到什么落地效果**"）
- **亮点提炼方向（突出落地实践）**：
  1. **架构设计**：NestJS 模块化分层 + 依赖注入，解决代码耦合、难以维护和测试的问题
  2. **混合存储与数据一致性**：MySQL + MongoDB 多数据源选型，通过 TypeORM QueryRunner 事务解决项目级联删除的数据一致性问题，避免生产环境脏数据
  3. **AI 模块容错设计**：针对大模型调用不稳定、返回格式不可靠的生产问题，采用适配器模式+重试机制+Schema校验+兜底方案，保证 AI 功能在生产环境的可用性
  4. **流式响应体验优化**：SSE 实现流式输出，解决大模型响应慢导致的用户体验差问题，首字延迟从3s降至300ms；考虑连接异常处理
  5. **性能与稳定性**：多级缓存设计解决热点数据查询性能问题，接口限流防刷防止恶意请求，全局异常捕获统一错误响应避免服务崩溃
  6. **生产级工程化**：JWT 认证与密码加密、参数校验防御非法输入、结构化错误日志便于线上问题排查、数据库事务保证操作原子性、CORS 跨域配置等

## Assumptions & Decisions
- 内容控制在简历项目描述的合适长度（约 600 字）
- 保留量化数据体现效果（性能提升、延迟数据等）
- 每个技术点都关联一个"解决了什么生产问题"，体现落地经验而非纸上谈兵
- 采用"问题→方案→效果"的结构，符合 STAR 法则
- 不需要实现代码，仅输出文字内容
- 重点突出生产环境会遇到的实际问题：大模型不稳定、数据一致性、异常排查、性能瓶颈、恶意请求等

## Verification Steps

- 确认每个亮点都体现了解决实际生产问题，有落地感
- 确认内容精炼，适合简历使用
- 确认覆盖架构、数据、AI容错、用户体验、性能稳定性、工程化六个维度
