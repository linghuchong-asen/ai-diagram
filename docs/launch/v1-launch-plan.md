## 1. 发布定位与核心决策

### 1.1 发布策略：免费公测（Limited Free Beta）

**决策**：明日（10-21）发布版本定位为「商业化体系的第一次公开亮相」，形态为**免费公测 + 每日配额**，而非直接收费。

**理由（技术事实决定）**：
- 支付/订单/会员代码**不存在**（全库搜索 payment/order/subscription/套餐/会员 零命中），一天内无法安全上线收费能力；
- 无域名、无 ICP 备案，公开收费在合规上不可接受；
- 配额系统（每日生成 200 次 / 修改 500 次 / 50 万 token）已上线，它本身就是商业化基础设施——**配额即付费钩子**：公测期用配额培养习惯，未来"提额"就是付费点。

### 1.2 本次发布包含的新增能力（2026-10-20 加班完成）

| 能力 | 说明 |
|---|---|
| 品牌露出 | 站点标题/描述/OG 标签、登录注册页"语图 Yutu"品牌头、首页"语图 · 我的图集" |
| 法务合规页面 | `/agreement` 用户服务协议（10 条）+ `/privacy` 隐私政策（8 条，含第三方模型披露）；注册强制勾选 |
| 配额可视化 | 新端点 `GET /api/ai/quota`，AI 浮窗实时显示"今日额度：生成 x/200 · 修改 x/500" |
| 存活探针 | 新端点 `GET /api/health`（SELECT 1 探 DB），docker healthcheck 与巡检已切换 |
| 反滥用 | 登录限流（同 IP+用户名 10 次/10 分钟）、注册限流（同 IP 5 次/10 分钟），429 明确提示 |
| 测试修复 | 修复 5 个静默失败的测试套件（jest 路径映射 + spec 依赖补齐），24 套件 230 用例全绿 |
| 部署链路修复 | 仓库脚本与运行时路径分裂问题修复（原为发版阻塞项：仓库脚本会部署到错误目录） |

### 2.2 发版日 Runbook（验收清单）

发布顺序：**配密钥 → 构建 → deploy.sh（自动验证+失败回滚）→ 人工验收**

```
1. 配置 DASHSCOPE_API_KEY 到 /root/.cache/yutu-runtime/app/.env.prod（阻塞项，见 §6）
2. bash deploy/scripts/deploy.sh "商业化V1.0首发"
3. 自动验证通过后，人工验收（全部通过才算发版完成）：
   [ ] http://127.0.0.1/            → 200，页面标题为「语图 Yutu — 对话式 AI 流程图生成器」
   [ ] http://127.0.0.1/api/health  → 200 {"status":"ok","db":"up"}
   [ ] 注册新账号 → 强制勾选协议生效 → 跳转登录 → 登录成功
   [ ] /agreement、/privacy 页面可访问
   [ ] 创建项目 → 打开编辑器 → AI 浮窗显示「今日额度：生成 0/200」
   [ ] AI 对话生成一张流程图 → 预览 → 应用到画布（DASHSCOPE 密钥生效的真实证据）
   [ ] 连续错误密码登录 11 次 → 第 11 次返回 429「尝试过于频繁」
   [ ] docker ps 三容器 healthy；巡检脚本 bash deploy/scripts/inspect.sh 全 [ OK ]
4. 外部网络验证（办公网/手机热点）：访问 http://8.140.203.51/ 可打开（阿里云安全组 80/TCP 已放行）
```

### 2.3 回滚方案

- deploy.sh 内置失败自动回滚（上一 tag 保底）；
- 手动回滚：`bash deploy/scripts/rollback.sh [tag]`（VERSIONS 台账选版本）；
- 数据兼容性：本次无破坏性 schema 变更（ai_daily_usage/auth_tokens 等表均已存在），回滚无数据风险。

## 3. 运营保障

### 3.1 已就绪（自动运行中）

- 每日 02:30 PG 全库 + uploads 备份，保留 14 天（已连续成功）；
- 每日 08:00 自动巡检（本次已增强：/api/health 探针 + swap 深度使用检查），连续 2 天全 [ OK ]；
- 每周日 03:00 应用日志清理；
- 旧镜像清理已纳入 deploy.sh 发版流程（保留 latest+当前+上一版本）。

### 3.2 已知资源风险

- 服务器 3.6G 内存 + 4G swap，swap 已用约 3G（发版日为流量峰，关注 OOM）；
- 磁盘 67%（已清理旧镜像回收约 3.5G）；若用户增长超预期，优先考虑升配（4C8G 起步）。

### 3.3 客服与反馈渠道（发版日最低配置）

- 用户协议页公示支持邮箱（当前为占位 `yutu-support@example.com`，**发版前必须换为真实邮箱**）；
- 产品内 AI 浮窗的报错信息已是可读中文文案，降低求助量；
- 缺失：忘记密码自助通道（用户体系仅账密）。**发版日风险最高的运营缺口**：密码丢失=账号丢失。缓解：客服邮箱人工找回（核实注册信息后由管理员重置），文档中明确公示此流程。

## 4. 推广计划（冷启动）

### 4.1 渠道（按 ROI 排序，零预算冷启动打法）

1. **技术社区内容营销**（主渠道）：掘金/知乎/V2EX/即刻 发布「我们把 LLM 做成了流程图引擎」类技术+产品文，附在线体验地址；流程图是程序员高频刚需（技术方案、链路梳理、审批流），匹配度高；
2. **微信生态**：朋友圈种子用户（团队人脉）+ 相关社群（架构师/产品经理群）定向分享；
3. **即刻/小红书产品圈**：以「AI 效率工具」角度发体验帖，附生成效果 GIF（GIF 比文字链接转化率高一个量级）；
4. **高校/社团渠道**（备选）：流程图面向课设答辩、社团招新场景，学生群体对免费额度敏感。

### 4.2 发布文案（示例，可直接使用）

> 「语图 Yutu」今天开放公测：**跟 AI 说一句话，流程图直接落到画布上**。
> "帮我画一个用户注册登录的流程" → 30 秒出图 → 不满意继续对话改 → 还能手动微调导出。
> 免费公测期每天 200 次生成额度，无需付费、无需邮箱，注册即用。
> 体验地址：http://8.140.203.51（公测版，域名备案后更新）

### 4.3 北极星指标与目标（首周）

- 注册用户 ≥ 100；次日留存 ≥ 30%；
- AI 生成成功率（done/总请求）≥ 90%（配额外消耗重点盯 4xx）；
- 每用户日均 AI 生成 ≥ 3 次（配额余量下降速度 = 价值验证）；
- 失败原因 Top3 每日归档（observability 模块已有 trace 查询接口支持）。

### 4.4 域名与对外口径（重要）

当前仅能以裸 IP 访问。**所有对外物料中注明「公测版」**，避免给用户"正式商业服务"预期；域名购买+ICP 备案完成后（预计 2-4 周，见 §6 合规）统一更换物料并做 301。
